# Unified local workflow

This branch does not ship `zotero_local.py`, `local_parse.py`, or `tests/test_unified_local.py`. Doctor does not require those scripts. Their absence is not a doctor failure. `run --feature unified-local` reports that absence and does not collect tests. Do not invent those modules or treat this note as a drive recipe.

The landed write is `zotero_ingest.resolve_write_target`. Default `ZOTERO_WRITE_BACKEND=auto` opens `http://127.0.0.1:23119/api` when `--api-base` is still `https://api.zotero.org`, then uses the Web API if Desktop does not answer. `run --feature unified-local` does not collect `tests/test_lab_defaults.py`. Those loopback tests are `run --feature lab-defaults`. They are not the missing `test_unified_local.py` suite.

`scripts/verify.py zotero-local` is a different check. It calls `capability.probe_zotero_local` on `http://127.0.0.1:23119/api/users/0/items?limit=1` and reports the Desktop API reachable on HTTP 200. It is not the missing `zotero_local.py` module. `capability.probe_zotero_local_write` returns true on HTTP 200 plus a `Zotero-Server-ID` header. `zotero_ingest.open_local_session` requires that header, then `POST /api/local/authorize` when `ZOTERO_LOCAL_API_KEY` is empty. Local API upload reads the artifact in `Writer.upload`, posts it with `POST .../file`, then posts those bytes to a same-origin `/api/local/uploads/` URL with `Zotero-API-Key` and `Zotero-Server-ID`. `GET /file` read-back uses `_LocalFileRedirect.http_error_302` to read the `file://` path from disk.
